# Установка на iPhone (сайдлоад)

Документ описывает, что именно даёт сборка, как поставить приложение на телефон
и **что в нём пока не работает** — чтобы не было сюрпризов после установки.

## 1. Две разные сборки, и они отвечают на разные вопросы

| Конфигурация | Зачем | Можно ли поставить на iPhone |
|---|---|---|
| `release_sim_arm64` | Проверка, что дерево вообще компилируется. **Подпись Apple не нужна вообще** | Нет |
| `release_arm64` | Сборка под устройство. Получается **неподписанный** `.ipa` | Да, после подписи своим Apple ID |

Сборка под симулятор бесполезна как продукт ещё и потому, что запустить современный
симулятор негде: собственный Mac mini проекта — 2012 года на macOS 10.15, туда встаёт
максимум Xcode 12.4. Его роль — быстрый ответ «код компилируется».

Поэтому порядок такой: сначала `release_sim_arm64` (проверка компиляции), затем
`release_arm64` для установки.

## 2. Что реально работает в приложении

| Фича | Состояние |
|---|---|
| **Сохранение удалённых сообщений** | Работает и **включено по умолчанию**. Данные пишутся в отдельную базу AyuGram |
| **История правок** | Работает, включено по умолчанию |
| **Даты прочтения** | Записываются (кто и когда прочитал) |
| **Ghost Mode** | Работает, **включить вручную**: Настройки → AyuGram |
| **Блокировка спонсорских** | Работает, **включить вручную**: Настройки → AyuGram |

## 3. Что пока НЕ работает — и это важно знать заранее

Данные собираются, но **посмотреть их в приложении пока негде**. Не реализованы:

- **экран «удалённые сообщения»** (в Android-версии — «View Deleted» с поиском).
  Записи лежат в базе, но UI для их просмотра нет;
- **экран «кто прочитал»**. Даты прочтения записываются, показать их негде;
- **regex-фильтры сообщений**. Движок написан и покрыт тестами, но к отображению
  чата не подключён;
- **списки фильтров рекламы (ABP) и блокировка в веб-содержимом**. Сделана только
  блокировка спонсорских сообщений в каналах.

Если после установки покажется, что «архив не работает» — он работает, просто его
нечем открыть. Это следующий этап, и он требует компилятора, чтобы писать UI
не вслепую.

## 4. Установка неподписанного IPA (бесплатный Apple ID)

1. Скачай артефакт `ayugram-ios-release_arm64-<номер>` со страницы запуска
   в GitHub Actions и распакуй из него `ayugram.ipa`.
2. Установи **Sideloadly** на Windows: <https://sideloadly.io>
3. Подключи iPhone кабелем, разреши доступ к устройству.
4. Перетащи `ayugram.ipa` в Sideloadly, введи свой **Apple ID**.
   Пароль идёт напрямую в Apple, никуда больше.
5. Нажми Start. Sideloadly сам подпишет приложение твоим сертификатом разработчика.
6. На iPhone: **Настройки → Основные → VPN и управление устройством** →
   доверься профилю разработчика с твоим Apple ID.
7. Запусти приложение. Настройки AyuGram — внутри: **Настройки → AyuGram**.

### Ограничения бесплатного Apple ID

- **приложение живёт 7 дней**, потом нужно переподписать. AltStore умеет делать это
  автоматически по Wi-Fi, пока компьютер включён;
- **одновременно можно держать не больше 3 сайдлоад-приложений**;
- **push-уведомления работать не будут.** Это не дефект сборки: APNs требует
  entitlements платного аккаунта разработчика. Уведомления появятся только при
  открытом приложении.

## 5. Платный Apple Developer ($99/год)

Даёт то, чего не даёт бесплатный:

- подпись нормальным сертификатом — **push-уведомления работают**;
- срок действия год, а не 7 дней;
- можно поставить provisioning профиль в секреты репозитория и собирать **подписанный**
  IPA прямо в CI, без Sideloadly.

Для этого добавь секрет `APPLE_TEAM_ID` и сертификат с профилем; шаги описаны в
README у Swiftgram/Telegram-iOS («Advanced Compilation Guide»).

## 6. Если что-то не так

| Симптом | Причина |
|---|---|
| Приложение падает сразу при запуске | Не подставлены настоящие `api_id`/`api_hash`. Сборка в режиме `credentials: placeholder` компилируется, но подключиться не может |
| «Unable to install» | Не доверен профиль разработчика, либо истёк 7-дневный срок |
| Нет уведомлений | Ожидаемо для бесплатного Apple ID, см. выше |
| Не приходят сообщения | Проверь, что `api_id` действительно от твоего аккаунта на <https://my.telegram.org/apps> |

## 7. Где лежат данные архива

База AyuGram — **отдельный файл на каждый аккаунт**, `ayugram-<id>.sqlite`, в
`Application Support` контейнера приложения. Это сделано намеренно: в Android-версии
архив тоже отдельная база (`ayu-data*`), а id канала одинаков во всех аккаунтах,
поэтому общий файл не смог бы не смешать историю двух аккаунтов.

Импорт архива из Android-версии AyuGram реализован на уровне схемы и миграций
(проверено тестами), но **пользовательского способа перенести файл в приложение пока
нет** — это тоже требует UI.
